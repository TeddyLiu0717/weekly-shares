# 一、先说痛点：为什么收藏了那么多，还是没有知识？

相信不少人和我一样：

- **收藏即吃灰**：微信文章、网页、飞书文档、视频网课，存了几百条，要用时一条都找不到；
- **RAG 问答问完就忘**：给大模型挂个向量库，问的时候确实能答，但这是一次性的——知识没有沉淀成结构，文档之间也没有关系，换个问题重新检索一遍；
- **手整理坚持不过两周**：分类、打标签、写摘要全靠人肉，断更一天，后面就再也不想打开。

我的思路转变只有一句话：

> **别让 AI 只回答问题，让它按一份固定协议，长期"维护"一个文件夹。**

工具不需要新的：**Obsidian（阅读）+ 任意能读写本地文件的 AI 智能体（Trae / Cursor / Claude Code / Codex 都可以）+ 一个纯 Markdown 文件夹**。

# 三、核心设计：四层架构，各层只做一件事

这套东西能长期跑下来，关键是分层。层与层之间定好契约，AI 只在被允许的层里活动：

![四层架构图](shots/scene-02.png)

- **第 1 层 · raw/ 证据层（只读、只追加）**：网页原文、文档导出、视频转写，进来什么样就永远是什么样。AI **无权修改和删除**；同一资料出了新版，也只能追加一个新版本，不能覆盖旧版。
- **第 2 层 · wiki/ 知识层**：AI 编译产物，只有四类页面——
  - `sources/` **来源摘要**：每份 raw 资料对应一页，是所有知识的"根"；
  - `concepts/` **概念**：方法、理论、框架，一个概念一页；
  - `entities/` **实体**：人物、公司、产品、工具；
  - `topics/` **主题**：跨多篇资料的综述，有必要才建。
- **第 3 层 · 索引与状态**：`index.md`（全局页面索引）、`log.md`（只追加的变更日志）、对象状态注册表（discovered → captured → complete）。
- **第 4 层 · Obsidian**：纯阅读和导航，人基本只在这一层活动。

资料在层与层之间走一条固定流水线：

![五阶段流水线与状态机](shots/scene-03.png)

**Capture（入库）和 Ingest（编译）严格分开**是刻意设计的：入库时 AI 不许"顺手总结"，因为一旦总结错了，你就永远失去原文了。

# 四、手把手搭建（5 分钟跑通）

## Step 0：准备工具

- [Obsidian](https://obsidian.md/)（免费，本地版即可）
- 一个能读写本地文件夹的 AI 智能体（本文不挑工具）
- Python 3（可选，只用来跑体检脚本，纯标准库零依赖）
- Git（可选，用来备份/同步）

## Step 1：建目录骨架

```text
my-kb/
├── AGENTS.md          # 知识库宪法：AI 的红线和工作流（最重要的文件）
├── raw/               # 【只读】原始证据
│   ├── web/  docs/  local-files/  videos/
├── inbox/             # 临时收件箱（随手存的链接、灵感）
├── wiki/
│   ├── sources/       # 来源摘要
│   ├── concepts/      # 概念
│   ├── entities/      # 实体
│   ├── topics/        # 主题
│   ├── index.md       # 全局索引
│   └── log.md         # 变更日志（只追加）
├── templates/         # 四类页面模板
├── config/            # schema、入库规则（AI 只读）
├── prompts/           # 可复用指令
├── scripts/kb.py      # 体检脚本
├── attachments/
└── drafts/            # 你的私人草稿（AI 只读）
```

## Step 2：写 AGENTS.md——给 AI 立"上岗协议"

这是整个体系里最有价值的一个文件。AI 是个执行力极强但边界感为零的实习生，**你不写清楚，它就敢乱写**。我的协议里有八条红线，最关键的是这四条：

1. **`raw/` 只读、只追加**：不许修改、覆盖、删除任何历史文件；新旧说法冲突时并列保留，不许替我裁决；
2. **没有来源引用，不许把推断写成事实**；AI 自己的归纳必须标注 `> 推断，待确认`；
3. **信息不足就标"待核实"，禁止编造**具体数字、日期、人名、版本号；
4. **没更新索引、没写日志、没过体检，不许声称"已完成"**。

另外两条工程性约定：

- **人机内容分区**：AI 生成的内容只能写在成对的 `<!-- AUTO:START -->` / `<!-- AUTO:END -->` 标记之间。区块外是我自己写的东西，它再跑 100 次自动维护也冲不掉；
- **默认不写入**：普通聊天、讨论、排查过程一律不进库，只有我明确说"入库/保存/沉淀/留档"才落盘。

## Step 3：定义四类页面模板

每页都有统一的 YAML frontmatter：

```yaml
---
title: 页面标题
type: source-summary   # concept / entity / topic
created: 2026-10-29
updated: 2026-10-29
sources: []            # 依据的来源页；concept/entity/topic 至少 1 条
tags: []
---
```

来源摘要页的核心长这样（注意 AUTO 区块和"核心观点"而不是机械摘抄）：

```markdown
## 来源
| 字段 | 值 |
|---|---|
| 链接 | https://... |
| raw 路径 | raw/web/xxx.md |

<!-- AUTO:START summary -->
## 内容摘要
（2-3 句话说清楚这份资料在讲什么）

## 核心观点
1. ...
2. ...
3. ...
<!-- AUTO:END summary -->

## 关联
- 概念：[[检索增强生成]]
```

规则很简单：**概念/实体/主题页不允许"无源之页"**，每一条事实都能沿着双链回溯到某份 raw 原文。

## Step 4：第一次"入库"和"编译"

在智能体里打开这个文件夹，第一句话让它读协议：

> 阅读 AGENTS.md，然后熟悉一下这个知识库。

之后把一篇文章丢给它：

> 把这篇文章**入库**，下周做竞品分析要用。

它只做 Capture：检查正文/链接/作者/日期和附件，把**原文**写进 `raw/web/`，给你一行回执，不动 wiki。

然后说：

> 把待编译的资料**编译**一下。

它会先读 `index.md` 查重（能补充旧页就不建新页），产出"来源摘要 → 概念/实体 → 必要时的主题页"，建好双链，更新 `index.md` 和追加 `log.md`。**单批最多 10 篇**，超过会自动分批。

## Step 5：质量门——每批编译完自动体检

我写了一个零依赖的 `kb.py`（Python 标准库，Windows/Mac 都能跑），把所有规则变成可执行检查：

```powershell
python scripts/kb.py doctor   # 断链 / frontmatter / 空摘要 / AUTO 块 / 孤立页 / 索引覆盖
python scripts/kb.py stats    # 各层页数
python scripts/kb.py todo     # 还有哪些 raw 资料没编译
```

AI 编译完必须自己跑一遍。下面是脚手架示例库的真实输出——第一次跑出 2 个严重项，返工后才转绿：

![质量门体检：不过当场返工](shots/scene-07.png)

发现"严重"项时脚本退出码为 1，所以它也能直接挂到 CI 或定时任务上做告警。

## Step 6：让它每天自动增量

把日常那句话固化成定时任务。我自己的生产环境是智能体每天定时执行"每日增量"指令（脚手架 `prompts/04-daily-increment.md` 可直接用）：

1. 扫描信息源，按上次水位列出"新增/更新"对象并去重；
2. 新对象走 Capture；没权限、原文缺失的标 `blocked` 并写明原因；
3. 可执行对象每批 ≤10 篇走 Ingest，过质量门才进 wiki；
4. 跑 `kb.py doctor`，给当日回执：新增 X 页 / 更新 X 页 / 阻塞 X 项；
5. 推进水位；拿不准的事列清单等我拍板，**不许猜**。

Windows 上想让体检每天自动跑，一条命令装计划任务（脚手架自带）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-daily-task.ps1
```

# 五、三条用真实翻车换来的经验

![三条核心规则](shots/scene-08.png)

**1. raw 层不可变，是一切可信度的前提。**
AI 会幻觉，而且敢把数字和日期编得有模有样。只要原文在，任何结论都能回溯；原文没了，这个库就是一座装修豪华但地基是泡沫的房子。我早期做过一次交叉验证，AI 产出的事实性条目错误率并不低，从那以后"只读证据层"就是第一铁律。

**2. 不要追求全自动，要追求"人只做判断"。**
冲突观点并列保留、跨来源归纳明确标注"这是 AI 的推断"、拿不准就停下来问。自动化接管的是搬运和编译，判断权始终在你手里。把 partial 报成 complete 是 AI 最容易犯、也最危险的"讨好型错误"，协议里要明令禁止。

**3. 先跑通闭环，再谈规模和向量检索。**
新手最容易上来就研究 chunking、embedding、向量数据库。但我的体感是：**结构比检索重要**。先用 20 篇资料跑顺"入库 → 编译 → 体检"，养成"每篇资料都有根"的习惯；等 wiki 层厚了，全文检索 / 向量检索只是加在上面的一个查询入口而已。

# 六、常见问题

**Q：和直接用 Notion AI / 各种 AI 笔记 App 比，优势在哪？**
A：数据是纯 Markdown 文件和文件夹，不被任何云格式锁定，十年后还在；AI 可以用文件系统原语直接读写，协议你自己定，而不是被 App 提供的功能边界限制。

**Q：不用 Obsidian 行不行？**
A：行，VS Code、Typora 甚至资源管理器都能读，Obsidian 只是提供双链、图谱和反向链接的最好用的"壳"。

**Q：AI 在 AUTO 区块外乱写怎么办？**
A：靠 AGENTS.md 协议 + `kb.py` 体检双保险；真不放心，还可以把 `drafts/`、`config/`、`templates/` 设成只读权限，从文件系统层面兜底。

**Q：公众号文章、视频怎么入库？**
A：文章存原文 Markdown 到 `raw/web/`；视频先转写文字到 `raw/videos/`，链接和待转写标记留在 `inbox/`。
